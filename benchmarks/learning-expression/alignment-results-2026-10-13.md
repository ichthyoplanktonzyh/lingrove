# 语块切分与对齐提示词实验：2026-10-13

已完成 756 次正式请求：28 个固定原文/译文对 × 3 个模型 × 3 个提示词版本 × 3 个种子。另有 72 次试跑和各模型的冷/热校准，不进入正式统计。

结论：在两款通用模型中，先去掉解释职责的收益明确。当前精简二维数组方案更快，但需要明确语块粒度；尤其 Gemma 经常以整句单组完成任务，不能直接按程序校验通过率采用。当前测试中，Gemma 的 B 组最符合学习目标。

## 对照与边界

- A：当前生产提示词，生成对应关系和解释。
- B：仅去掉解释职责，保留对象、NDJSON 和不连续片段能力。
- C：连续片段的二维数组；同时简化规则与结构，是整体方案实验，不能把 B→C 的差异只归因于数组格式。
- 译文是人工校验后冻结的输入，三组相同；本次不重新评价翻译能力或解释质量。模型没有收到审查预期。
- 每个模型内部固定采样、8192 上下文、4096 输出预算、关闭思考，种子 42/43/44。请求按单模型串行执行，组别轮换；不加载旧 14B 或 Ministral。
- 本机 M1 Max 32GB，Ollama 0.40.3，仅数值 loopback 地址；没有外部传输。Gemma E4B 是文本 GGUF，元数据标注总规模 7.5B，不能当作普通 4B 权重比较。Hy/Qwen/Gemma 均 Q4_K_M；Hy 采用独立的官方采样配置。

## 关键观察

1. 去掉解释的收益在两款通用模型中一致。相同原文、种子且 A/B 都通过的请求，B/A 完成时间比中位数为 Qwen 0.524（n=30）、Gemma 0.526（n=76）。Qwen A 有 5 次跑满 4096 token；B/C 均无。Qwen A 所有请求的 P95 约 99.32 秒，不能只看成功子集的 3.45 秒。
2. C 改善了 Qwen 的实际可用结果数，但仍有遗漏外层数组、空数组、错误摘取等问题。B/C 共同通过的 35 对请求，C/B 耗时比中位数 0.615；这是整体方案收益，非格式单因素结论。
3. Gemma C 的 84 次全部通过程序校验，却有 60 次只输出一个组；B 为 15 次。部分短问候整块合理，但报告长句等也整块返回，导致语块学习价值下降。B/C 共同通过的 80 对请求，C/B 耗时比中位数 0.701，额外加速需要结合这个粒度损失理解。
4. Hy-MT2 的 B 没有格式合法输出，C 仅 2 次合法且都是空数组。该本地配置未能稳定遵守结构化对齐协议；这不否定它的翻译能力，也不证明其他提示词/运行时一定失败。
5. 否定、时间、重复表达和技术表达仍有真实错配，程序可以拒绝不存在或重叠的片段，却不能仅靠文字定位确定语义对应正确。

例如同一个原文“我一到家就给你打电话。”及固定译文“I will call you as soon as I get home.”，Gemma 第一次 B 输出：

```json
[ ["我一到家", "as soon as I get home"], ["就给你打电话", "I will call you"] ]
```

上面将 B 的对象内容归一化展示，实际 B 请求/返回为 NDJSON。C 的原始返回为：

```json
[["我一到家就给你打电话。", "I will call you as soon as I get home."]]
```

对应意思完整，但用户无法直接看出两个结构的表达关系。另一条长报告句在 B 中分为原计划、今天发送、核实数字、可能延期四块，在 C 中整句成块。

## 下一步建议

保留模型只负责片段与对应关系、程序生成编号/范围/颜色的方向。下一版继续使用二维数组，但保留明确的切分责任：普通句子需给出有学习价值的多个语块，不能用整句单组绕过切分；短问候/固定表达可例外，长句先按分句再按完整结构处理。提示词直接展示完整外层数组示例，同时强调片段原样摘取和固定译文。先做同样固定输入的小范围 C2 对照，确认粒度改善且对应未退化，再改生产解析器与提示词。此建议尚未作为新实验运行。

当前若选择一个继续优化的本地分析候选，优先 Gemma + B；Qwen + C 作为更小权重候选，仍需修格式与对齐错误。语块分析继续与快速翻译独立，暂不把这项职责交给 Hy-MT2。
