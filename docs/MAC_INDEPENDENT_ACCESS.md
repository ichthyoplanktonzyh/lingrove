## 目标与明确边界

让现有 AppKit/SwiftUI Mac Lingrove 具备可用的账户接入基线：原生工程/设置入口、
同一后端协议的邮箱验证码登录、私有凭据、身份确认、会话恢复/刷新和退出。保留菜单栏、
全局输入与补全、写作/阅读和现有模型配置。独立登录不依赖语料同步或复习核心完成。

- 直接沿用现有 Mac target 和生命周期，不改成 Catalyst，不另造第二个产品宿主。
- 本轮不提取/修改共享仓储、数据库 schema、同步、媒体或复习核心，不接通语料上传，
  不改语料归属；登录成功与同步成功分开表达，不能展示并不存在的同步状态。
- 优先复用基线 Nibomo 已平台无关的认证协议/实现。需要 Mac 适配时使用独立边界，
  不整块复制 `FlashcardsStore`/`CloudSessionRuntime`，不建新后端账户或不同身份规则。
- 最低交付为现有邮箱 OTP 的完整登录闭环。Apple/Google 等原生 provider 的 SDK/
  真实应用登记与统一账户 SDK 接入留待后续对齐；不要为未实现的方法放置可点击假入口。
- 当前没有用户数据，不承担旧 schema、旧快照或 Anki 绑定/历史迁移。今后使用中的
  凭据、账户切换、取消和重启仍须正确，不扩张清理无关旧功能。

## 完整交付行为

1. 原生设置中增加账户入口与可理解的连接配置/状态。明确未配置、未登录、处理中、
   已登录、离线/需恢复、凭据失效等状态；错误不展示令牌或未经清理的服务端正文。
2. 按既有 auth/API 协议请求邮箱验证码、提交验证码、确认可信用户身份。重发、取消、
   过期、错误验证码和失败重试有确定状态；不能仅凭解析 token 就伪造服务端已确认。
3. 凭据使用 Mac 私有 Keychain，绑定产品/环境及服务范围；Dev、正式应用和合成测试
   不共用凭据命名空间。生产路径不得回退明文文件/UserDefaults 保存 refresh token。
4. Mac 启动按配置恢复会话；刷新单飞，处理 token rotation、过期、网络失败及失效。
   登录尝试、切换服务、退出及迟到回调由明确代次/任务身份隔离，旧请求不能重新登录。
5. 退出取消/失效化在途认证任务，按既有服务支持的退出语义清理本机私有凭据；
   不调用虚构 API、删除账户或承诺本机退出等于撤销所有设备会话。
6. 应用只持有一个长期账户服务，复用 `LingroveAppEnvironment`/`AppDelegate` 所有权；
   设置窗口只观察状态和发起操作，窗口关闭/重开不新建认证或刷新服务。
7. 账号失败或未登录不阻断现有本地补全、翻译、阅读、语料和 CLI。启动不自动连接
   Nibomo 官方服务或创建云 guest；只有明确配置/操作触发认证网络请求。
8. 输出稳定且窄的身份/服务配置/状态与事件接口，后续公共 SDK/仓储可替换实现。
   workspace 信息若有读取仅作可信 metadata，不将它采用到本地语料或启动同步。
