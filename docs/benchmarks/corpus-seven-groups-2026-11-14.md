## 改了什么，为什么

1. 复习将练习、Card、材料可用性和可撤销事件批量分组，取消逐成员查询；未变化的语料标签和组顺序由会话索引复用。
   状态和队列仍来自本次事务，语料失效会清空派生索引。
2. 文字筛选保留每个词条的检索字段，复用重复字段的匹配决策；非 ASCII 内容保留本地化匹配。
   有连续回执的新增/移除可更新局部检索文档；移除有关联的意义目标、语义变化或缺少回执时保留完整路径。
3. CLI 单条/批量读取只解码所选词条及其证据/语义依赖，空查询列表只读当前页摘要。
   返回值是带版本的只读投影，不会把部分语料填成 UI 全量缓存或写入依据。
   分页显式选择现有父词条索引，避免 SQLite 为满足 ID 排序而扫描全库义项。
   状态查询在版本及数据库变更标记吻合时复用已有检查状态；冷读取只作 SQL 计数。
4. 收藏和编辑通过索引定位当前词条及重名所有者，减少全库键归一化和证据连接；完整消费者仍得到连贯的完整提交结果。
5. 手工批量导入只计算最终触及行的差异，提交一个事务/日志/版本。
   撤销合并仅保留词条、自有模式/关联、必要图片和精确版本，共享节点、关系和分类继续由当前状态拥有。
6. 一个类型更新批次复用一次解析结果。名称、CSS、默认类型更新不改写 Card 材料；字段/模板更新仍原子刷新全部实际引用者，保留 Card 身份、调度和评分。
7. 备份恢复取消 archive 的重复全图校验，引擎继续在写入前完成一次完整校验，媒体和封装检查保留。

## 保留的实际成本

首次全量检索准备 540.941→524.904ms，首次文字筛选 534.131→493.527ms；本批没有据此宣称显著加速。
移除有关联义项后的检索准备 204.023→198.335ms，也没有显著收益。连续收藏后的局部检索准备收益更明显。
完整规范语料读取 8462.010→8178.954ms，仍需读取/解码和校验全量数据；这不是分页首屏就绪时间。
完整备份写出约 2.19s，未作显著加速宣称。共享模板内容变化仍需实际更新 4,000 条 Note 的派生卡面。

本轮到这些有实测依据的边界收敛，未加入 SQL 语句池、新的持久化格式或额外后台缓存层。

# 全部窗口与计时口径

配置：Release / arm64 / ENABLE_TESTABILITY=YES；所有样本通过测试调用生产业务代码，没有模拟点击。

共 84 个计时窗口、378 个样本。其中 35 项每档独立重复 3 次；其余为每档单次完整扫描。

表中列名是初始词条数量，单位为毫秒。样本数大于1时显示中位数（最大值）；样本数为1时只显示单次观察值，没有统计稳定性保证。重复测量使用接近种子状态的独立副本；扫描内按固定顺序执行全部操作。

首次加载指新连接和新模型的首次访问；不含应用组合根/Repository初始化，也没有清空操作系统文件缓存。后续写入使用另一条等价内容，不是重复保存造成的无操作。

每个试次从同一档合成种子重新复制，按固定顺序执行；试次之间互不累计。单次试次内会新增和移除少量内容，原始样本记录每项执行前后的可见词条数。

存储总耗时计到 VocabularyStore 应用结果并发布状态为止；不含 SwiftUI 实际绘制、等待动画、下载、远端网络或模型生成。检索、列表和图谱投影另行列出。CLI不含进程启动和邮箱IPC。

阶段窗口使用独立调用，不能将不同调用的中位数相加解释成一次请求的总耗时。图片用80×40的合成PNG，不能代表大图片或媒体密集库。

两组删除样本同时改变了位置与语义关联：第59词条有关联，倒数第2词条无关联。它们是两个真实场景，不是隔离关联因素的对照实验，不能将差异全部归因于关联。引擎分段删除使用第65词条。

微秒量级的缓存读取接近测试调用与计时开销，不据此比较微小差异。

个人笔记变化的检索计时没有改变检索字段，主要验证避免多余重建；它不能代表义项定义或共享义改变后的检索重建耗时。
