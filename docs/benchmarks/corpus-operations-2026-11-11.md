原完整扫描在 2 万档 CLI 重试处因测试复用过期包而中断，成功前缀保留，修正后的独立尾段原生执行通过。
这不是一次从头到尾全部通过的完整扫描；原中断记录、补测范围和每行数据来源均保留。

本轮只增加测量工具和报告，没有修改业务实现。生产代码基线为 `093608d4`。
所有数据由测试生成，使用独立 SQLite 文件和独立测试宿主；没有读取、复制或替换安装版 Dev 的语料。

## 从数据和调用链可以得出的判断

### 完整保存路径需要优先处理

取消一条例句收藏、新增义项、移动或合并义项、手工录入等部分入口仍由
`VocabularyArchive` 构造完整文档并提交。`LingroveNotebookStore.saveInTransaction` 用
`changesMaterial` 判断是否刷新复习材料；需要刷新时传入的范围是 `nil`，表示全部。

`ReviewNoteStore.refreshInTransaction` 随后遍历已加入复习的 Note；
`reconcile` 和材料刷新会调用 `NotebookReviewNoteCard.source`，而单词条来源投影仍会扫描
解释、出现位置和来源数组。将这个单条读取放在全部 Note 的循环中，会重复扫描同一批语料。
这是明确存在的放大链路，与密集复习条件下的慢项相符；各段贡献比例没有通过调用栈采样独立量化，
不能把完整保存的全部耗时都归给其中一个函数。

下一步应先从已产生的行差异推导受影响的义项，限制复习材料刷新范围，并复用一次构建的来源索引。
原子提交、工作区隔离、关系检查、手工编辑和复习历史保留仍需要保护，不能通过跳过这些规则换取速度。

### 局部收藏仍存在随全库规模增长的事务成本

单独测量的收藏规划约为 47 / 96 ms，引擎事务约为 446 / 940 ms，读取索引增量约为
1.7 / 4.6 ms（分别为 1 万 / 2 万档）。这些是独立调用的窗口，不能将中位数相加还原另一条请求。

当前主要等待发生在引擎事务完成之前，列表准备和索引发布的成本小得多。
局部写入的检查、媒体引用处理、规范数据扫描和行投影仍需要进一步缩小范围；这不等于 SQLite
插入几个新行本身需要这么久，也不能据此认定实际 UI 绘制没有额外成本。

### 删除存在顺序位置更新的放大

`VocabularyEntryRowProjection.applying` 会调整删除点之后的解释、收藏和相关语义行的位置。
`recordRepositioned` 已经按 200 行批量执行 SQL，并复用存储中的 payload，避免删除重插和重复编码完整内容；
但它仍然需要更新大量后续位置并记录日志。前部删除和尾部删除因此具有不同的工作量。

下一步应增加实际变化行数和分段计时，再用位置匹配的关联/无关联样本验证各自贡献。
若调整排序的持久化表达，需要同时检查同步、导出和解码的顺序约束。

### 完整提交还可能增加下一次普通操作的成本

在完整扫描的操作顺序中，紧接完整保存的一次笔记保存约为 4.44 / 10.20 秒，
而独立热库样本约为 0.46 / 0.98 秒。
1 万档中，紧接全库标签删除的图片准备约为 3.96 秒，紧接批量保存的幂等 CLI 重试约为 3.87 秒。

这些窗口包含前序操作的影响，不能将它们全部算作 PNG 处理或重复写入。
`VocabularyArchive.perform` 会先读取保存状态，缓存失效后可能需要重新解码语料。
“完整保存后如何复用已验证状态”值得做配对验证；当前样本不是独立隔离缓存因素的实验。

### 另发现一个删除正确性问题

采用 Note 模板的已加入复习义项，在本轮副本中删除时返回
`ReviewTemplateError.sourceUnavailable`。测试验证拒绝后目标义项和库版本没有改变。
这项记录是拒绝耗时，不是成功完成删除的耗时。

调用链中，`ReviewNoteStore.refreshInTransaction` 会先执行需要原义项存在的 `reconcile`；
后续可以标记来源不可用的材料处理尚未执行就已经抛错。修复时应保留已有 Card 的记忆状态和评分历史。

### 已优化路径和后续优先级

在 1 万档的单次完整扫描中，生词本内加入复习约为 42 ms，首次进入进度页约为 57 ms，
评分并刷新约为 231 ms。这些路径与几十秒级的完整保存应分别看待。

建议先修复 Note 来源删除失败，再处理完整保存的全量材料刷新和重复读取；随后优化局部收藏、
前部删除的位置更新，最后评估首次加载和检索准备。现有 repository、actor IO、不可变结果、
作用域校验和领域失效边界可以保留，重点是让变化范围贯穿下游，而不是重写整个应用架构。

