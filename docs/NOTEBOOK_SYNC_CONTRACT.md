# 语料实体同步契约（内部验证阶段）

当前实现包含服务端带类型的语料写入/读取模块与原生纯值转换模块，尚未开放 HTTP/MCP，
也未接入移动端网络上传、分页拉取或账户迁移。完整目标仍按 [移动计划](MOBILE_NOTEBOOK_PLAN.md) 推进。
字段定义以 [`fields.ts`](../Nibomo/apps/backend/src/notebook/corpus/fields.ts) 为准，修改
与身份契约以 [`contract.ts`](../Nibomo/apps/backend/src/notebook/corpus/contract.ts) 为准。
它们没有复用 SQLite codec 的 opaque payload、索引或整本备份格式。

## 身份、顺序与材料

词条、义项、来源、出现位置、解释判断、收藏及意义/分类关系分别拥有身份。子记录
使用有业务含义的 owner 引用；选择、解释和证据连接的组合 key 保留既有身份范围。
`rank` 表示领域数组顺序，同 rank 的独立新增项按稳定身份排序，原生适配须在组装文档
时重新形成连续位置。父记录不复制一个会覆盖并发新增项的完整子 ID 数组。

UUID 使用小写字符串。未知学习语言保持 null，不能因界面语言而改成英语；分类语言
标签是另一种值。明确的 presence 字段区分原文档中的 nil 与空内容/复习卡/模板集合。
设备专用的 Anki binding、active binding、音频回执、provider 地址、缓存文件名和
持久化索引不进入这些字段。计划和模板保留准备材料及用户选择，存在计划不表示
选入内置复习。解释的本地 `occurrenceIdentity` 不作为远程字段；原生转换重建当前已
接受例句的派生键（包括未收藏例句），并保留候选/拒绝判断的本地身份快照。
完整窗口和应用存储提交仍由宿主负责。

时间使用明确的 Foundation reference seconds：自 2001-01-01T00:00:00Z 起的有限
Double 秒数，保留分数精度。它不是 Unix 秒或毫秒。服务器提交序号、实体版本和
分类目录的 Int64 版本使用十进制字符串，避免 JavaScript 数值精度截断；本地文档
revision 继续独立保护本机提交。

## 提交与冲突

[`store.ts`](../Nibomo/apps/backend/src/notebook/corpus/store.ts) 在现有完整操作组事务中
计划所有修改，再校验包含未修改记录的最终图，最后一起写入规范实体、变更身份和
确认。创建不能覆盖已有身份或复活删除记录；删除要求完整的当前实体版本。旧原文
和 occurrence 保持不可变，修正内容通过新的证据身份及明确的引用变更表达。

普通字段按服务器字段版本合并：旧版本请求能修改未被另一端修改的字段，同字段
不同值则冲突。`updatedAt` 只是时间来源信息，不能把编辑器对其他义项的时间戳更新
当成业务变化。明确的 add-only 操作保留独立新增的注释/引用；字段 reset 版本阻止
旧追加请求越过一次明确替换，重新加入另一端刚移除的内容。新例句通过独立来源、
occurrence、解释判断与收藏连接增加，无需重写父义项。

整组校验不替调用者静默删除证据或修理导入。变更已引用的解释证据时，业务命令须
明确撤回并将意义映射标为 proposed，或明确重新确认该证据。内置分类从创建、归属
转换到修改均受只读保护；客户端 JSON 不提供通用目录安装权限。普通初次上传可携带
服务端已捆绑的完整 `lingrove.core` v4：仅允许创建 ID 和所有定义字段完全相同的行，
只排除代表语料数组顺序的 `rank`，且最终图必须包含全部 652 条官方定义。补入可信
部分安装所缺的原样行也须满足同一完整性条件。修改、删除、归属转换、未知目录/版本
和墓碑复活仍拒绝。用户自定义分类、个人成员关系与覆盖继续单独管理。

## 存储与后续传输

规范行一次只保存一个实体，字段由完整 schema 校验。正文使用 PostgreSQL `json`，
以保留原模型允许的转义字符；`jsonb` 会拒绝 U+0000，见 [PostgreSQL 18 JSON 文档](https://www.postgresql.org/docs/18/datatype-json.html)。
本实现不在 SQL 中提取或转换正文 JSON；字段合并和关系检查由带类型模块负责。

提交日志只保留变更身份，避免建立永久的私人正文编辑历史。后续 pull 必须先固定、
物化并原子应用完整当前状态窗口，不能把身份日志当作历史值回放，见
[ADR 0002](adr/0002-corpus-current-state-windows.md)。内部固定窗口、原生分阶段暂存及
本地原子应用已实现；网络/媒体传输、上传确认、受管理练习及真实客户端验收仍需完成。
不得把超过
单组上限的语料简单拆成会暴露半个关系图的独立提交。

## 原生文档边界

[`LingroveNotebookSync`](../Packages/LingroveNotebook/Sources/LingroveNotebookSync/VocabularyWireProjection.swift)
直接读取规范领域数组，以明确的公开字段形成远程实体；不借用本地 SQL payload 或备份。
重组入口只接受宿主已确认完整的窗口，拒绝缺根、未消费的子行、未知字段和无效领域图，
不调用会修理/裁剪内容的 `prepare`。它无法自行判断传输是否遗漏一个无引用的独立记录。

私有状态按服务端生词本归属单独返回。绑定保留原始义项身份并可沿 `mergedFrom` 追溯；
音频回执仅在计划身份与公开材料均匹配时附着。远端已删除或改写的计划不会被私有状态
重建，未匹配值作为 `unattachedPrivateState` 返回，宿主必须将它与文档一起持久保存。
这个状态和整体 projection 刻意不提供 Codable，公开实体不能意外夹带工具地址、绑定
或音频文件名。当前模块没有网络、数据库、账户接管、复习选入或 UI 副作用。

历史本地校验允许同一 owner 下重复解释 UUID，而远程身份为 `ownerID:explanationID`。
这种文档在投影时明确报 `duplicateEntity`，不会自动去重、改 UUID 或丢掉一条解释；
后续接管流程必须向用户呈现无法表示的输入，保留原本地数据。不同 owner 复用解释
UUID 仍合法。转换成功也不替代服务端组大小、权限、版本与最终图校验。

## 固定读取窗口

[`windows/store.ts`](../Nibomo/apps/backend/src/notebook/corpus/windows/store.ts) 在与写入相同
的生词本锁内捕获当前值与高水位。bootstrap 返回全部规范记录，包括 tombstone；
incremental 返回 `(afterSequence, highWaterSequence]` 内受影响身份的当前记录，每个
身份只出现一次。只含 key 的日志从不充当历史正文。未来日志裁剪须另加保留水位与
bootstrap 回退，目前不会悄悄跳过旧 key。

页是 typed `CorpusRecord[]` JSON 的连续 UTF-8 字节流，固定最多 256 KiB，通过 base64
传输，可跨 JSON token/实体/码点。下载者先验证并拼接原始字节，再解码 JSON；不能
逐页当成实体数组解析。`CorpusRecord` 包含版本、删除身份和字段时钟，与原生公开
`VocabularyWireEntity` 不同。宿主先完整更新自己的服务端 shadow，再提取 live entities
给领域重组器；本地未上传变更、私有状态和游标仍须在同一提交边界保留。

页 SHA 使用原始 bytes。顺序描述符是 `ordinal:sha256:byteCount` 加一个换行，按从零
开始的连续 ordinal 拼接后求 SHA256。manifest 使用
[`contract.ts`](../Nibomo/apps/backend/src/notebook/corpus/windows/contract.ts) 中固定 ASCII
行顺序，包含账户（UTF-8 base64url）、工作区、生词本、replica、窗口身份、模式、起止
游标、initialized、到期毫秒、记录/页/字节总数和描述符 SHA；最后也有换行。全部页和
完整 manifest 校验成功之前，不得推进本地游标。相同参数的未过期窗口可以重放，
重放不续期；release 只是幂等缓存删除，不能证明客户端下载或本地提交成功。

空书也有 `[]` 的一页两字节，`initialized` 只由不可删除的规范根决定；它为 false 时
不能清空已有本地书。十五分钟 lease 到期后拒绝读取；membership 删除立即级联清理。
维护任务每批最多处理 128 页（32 MiB）和 100 个已空 header，不清活窗口。代码复用
既有每分钟任务，尚未部署；失败会保留重试，同时继续原媒体工作负载，不上传语料遥测。
单次服务端物化仍持有书锁，内存包含当前实体及其 JSON/UTF-8 表示；没有宣称大规模
吞吐或真实多设备同步已验收。

原生 `VocabularyWireWindowAccumulator` 只验证分块与记录 framing，返回不可自行构造
的 `VocabularyWireVerifiedWindow`。`VocabularyWireServerShadow` 另行验证增量基线、
已知身份/字段时钟单调性与最终完整图；它不是本地编辑文档。iOS schema 29 的
`LingroveNotebookWindowStore` 仅持久暂存页，完成后复核绑定 generation 和租约；
该返回值不代表本地 apply、book 采用、pending 确认或游标已经提交。

## 原生三方合并与原子应用

`VocabularyWireRebase` 以已确认的服务端 shadow 为祖先，将本地公开投影的变化叠加到
新窗口。未初始化服务端仅以空文档充当逻辑祖先，不因此清空本地语料或虚构服务端根。
不同字段可合并；同字段不同值、并发创建同一身份、已更改对象的删除均明确冲突。
字段改后恢复原值仍保留版本边界，不能只比较当前文本来放过旧编辑。add-only 字段
只有在两端保留原前缀且服务端没有越过基线版本进行 reset 时才合并追加；不把任意
数组并集当成移除/重排的替代。合并后的完整图仍须严格验证，不自动修复孤儿关系。

iOS `LingroveNotebookSyncStore` 将准备与提交分开：准备读取文档和远端基线，事务外
计算候选及验证/暂存给定图片；提交再次比较本地与远端修订，检查账户/workspace
generation 和租约，再原子保存实体、文档修订、服务端记录/删除身份、游标和私有余项。
schema 30 的本地完整性摘要绑定这些远端头部、记录数量和原始存储字节，拒绝缺失
独立行或损坏游标。完成写入后再检查租约；过期或失败时全部数据库改动回滚。

本地 notebook ID 保持不变，另存可信账户/工作区下的远端 book/replica 对应，保留
卡片来源和复习归属。既有绑定不同的远端书须走明确迁移，不能借一次 pull 换绑。
相同 manifest 的重复提交返回最新本地文档，包含首次提交后的本地编辑。Anki/音频
未附着状态通过宿主私有格式保存；公开实体仍不含这些值。

普通下载应用不等于上传确认：历史本地语料日志、受管理 Card/评分 hold 和旧 outbox
保持原样，远端变化也不作为新用户编辑写入语料日志。下节的确认覆盖分支仅在完整
服务端确认与覆盖窗口都验证后清理已捕获的语料日志；受管理复习 lane 继续独立保留。
当前边界已接入 HTTP 调度；账户迁移、冲突处理界面及完整多设备同步仍未完成。

## 冻结上传与确认覆盖

`VocabularyWireUploadPlanner` 比较确认基线与当前公开投影，为 create、patch、delete
选择明确实体版本；追加只取原数组之后的后缀，替换/移除保持显式 set。不可变来源
不能换正文沿用旧身份。私有 Anki/audio 状态和 SQLite 索引/行 payload 不进入请求。
普通通道仍受服务端 10,000 成员/2 MiB 契约及本机编码上限约束，超限整组报错。
大图使用后述私有 staged 通道，不能拆成会露出半图的任意可见提交。

iOS schema 31 只保留一份未完成的冻结组，保存精确请求字节、公开发送目标、基线
游标和本地 journal 头部覆盖，并以摘要绑定账户、两端 book、replica 和全部字节。
超时/重启/同账户重连复用同一请求和 IDs；迟到回调仍须持有有效 generation ticket。
没有 receipt 时阻止普通 apply 推进旧基线；另一个任务已准备好的普通 apply 也会被
提交阶段的冻结组比较拒绝。无公开差异时返回 nil，局部日志尚保留，不冒充上传确认。

receipt 须精确匹配 group/book、有序完整成员和大于发送基线的 Int64 序号。持久保存
receipt 仍不删日志；随后窗口须覆盖该序号及每个成员的规范记录。尚未被后续写入
替换的已知字段须与请求相符。append 保留旧基线前缀和已发送项，允许另一副本先有
某个相同追加值：例如旧 `[a]`、另一端先加 `c`、本端 add `[b,c]`，规范值为 `[a,c,b]`。
这与任意数组并集不同，较晚的 reset 仍是不能跨过的边界。

合并使用冻结发送目标作为逻辑祖先、原始确认基线作为真实 shadow，并只对已写字段
使用 receipt 的时钟边界；发送后的本地编辑和追加继续保留。未发送的 timestamp-only
变化不写入逻辑祖先，恢复冻结数据也重新验证这一点。规范值始终来自覆盖窗口，
不根据 receipt 伪造服务端字段或游标。

最终事务原子完成文档/私有余项/shadow 更新、精确捕获 journal 头部的退役、简短
receipt ledger 插入和冻结组删除。较新的 journal、受管理 Card/评分 hold 及旧 outbox
不在该退役集合。完成 ledger 不留语料正文；下一组已存在时，旧确认仍可幂等返回。

原生支持下节所述终态结果，应用调度见文末。权限、超时或未知失败必须保留冻结请求；
单次冲突响应也不能证明旧请求永远不会提交。没有冻结请求时，planner 确认没有可上传
公开差异后，可在事务中复核原本地修订、远端状态修订、游标和完整 journal 头部，再
只删除捕获的已收敛/私有日志，不生成 receipt 或改变设备私有内容。冻结请求始终优先。
冲突处理界面、大图生产调度和完整多端网络验收继续按 M3 推进。

## 私有大图传输与 SQLite 确认恢复

staged 规划、分块暂存和最终提交使用同一份冻结公开操作组；完整正文和关系校验通过
后仍只产生一次原子领域决定。服务端保留上传身份和永久决定，临时正文可以清理。
上传进度、取消或过期不是语料 ACK/rejection，不能据此清除日志或重新使用旧 group ID。
普通接口及客户端的原预算不变，staged 的声明上限也不是经过资源验收的运行保证。

原生显式 opt-in 保存 `transport_kind=staged`，完整性摘要使用独立 domain，避免只改
标志就把普通冻结组升级。schema 33 的子表保存有界紧凑清单和确认页；清单绑定完整
scope、原始正文、决定及成员/分页摘要。页写入先使用已恢复的冻结值验证对应成员，
再在 SQLite 事务中核对 generation、冻结摘要、descriptor 和不可变清单。重开时重新
验证正文并逐页核对原始存储摘要、序号、全部成员及摘要根；缺页或损坏不会生成结果。

完整证明可在内存中生成原有 receipt/rejection，供同一覆盖窗口/合并路径使用；大数组
不进入旧 Codable 或 receipt 表。正向只退役冻结时捕获的日志，负向保留所有日志；最终
apply 把文档、shadow、日志处理、紧凑清单 ledger 和批次/确认页清理作为同一事务。
完成后仅保留小型清单及绑定信息，晚到回调核对同一决定，不能覆盖后来编辑或新批次。
旧 direct 请求和摘要原样升级，缺失 staged 子状态在普通重开时不自动修复。

生产 runner、能力声明和路由 composition 尚未启用 staged；私有选项仅用于显式联调。
schema 34 增加必备的传输状态子行和独立关闭 ledger，关闭不生成 group outcome。
本机取消意图与服务端关闭原因分开保存；用户取消后不凭重启或远端 apply 自动重传。
新本地日志只有实际公开内容改变才可解除门槛，私有回执和 updatedAt 变化不算；自动
解除与下一次冻结/无差异收口原子提交，失败保留门槛。显式重试本身是持久授权，成功
后即使在新冻结前重启也可继续。取消/过期后的 apply 使用普通三方合并，保留全部日志，
只在最终事务清理旧身份并保留紧凑关闭记录。确认与关闭互斥，取消晚于已提交请求时
仍须读取并完整核对正向确认。资源准入及生产接入仍待完成。具体运行证据见
[集成记录](NIBOMO_INTEGRATION.md)。

## 协商后的应用调度与后台存储

新客户端请求头 `X-Lingrove-Corpus-Features: staged-upload-v1` 只表示接受扩展，不能启用
服务端路由。默认能力响应仍不增加字段；服务端显式 staging 选项与所需迁移均就绪后，
才对该请求返回 `stagedUploads`，包含固定分块/确认/关闭协议及本次准入预算。创建新组
先走普通 planner，只有明确超限且协商成功才改用 staged；准入失败不冻结不可发送的新
组。已冻结请求不改正文或传输方式，缺失能力时保留原请求；本地完整证明或关闭状态
可继续走普通窗口合并，部分确认仍须恢复对应分页能力。

应用调度一次只结算一个冻结身份。读取服务端进度后只发送缺块，逐块检查本机取消，
确认页落库后重开也只读取缺页。闭合、过期及完整确认都先持久保存，再拉回校验窗口；
未知 HTTP 失败不换身份。关闭上传不会阻止普通拉取。明确「立即同步」可恢复用户取消，
下拉刷新只清除暂时错误门槛，不解除持久取消。

schema 35 为每个 staged 请求保存取消代次与对应的恢复授权。用户点击时只捕获已经
存在的取消及完成记录；后台提交该授权后，网络失败和重启不会丢失它。新 Cancel 增加
代次并撤销旧授权；旧授权不能恢复新请求，也不能跨账户 ABA。覆盖 apply 将该代次与
关闭记录一并保存，授权晚于正文清理到达时仍只作用于原取消。原直接请求及摘要不变。

SQLite 的整图读取、冻结/恢复、完整确认和合并写入使用同一主文件的后台临时连接，
每项操作内部检查捕获的账户代次。原连接在 await 前后继续检查，关闭原连接拒绝后续
调用；已派发操作拥有独立连接，可能完成已授权事务，后续按磁盘原身份恢复。HTTP
有界读取、JSON 解码和分块编码也移至后台，不传递可变数据库对象。

现有一分钟维护入口增加固定的上传清理函数，每轮最多删除 128 个分块/32 MiB，未完成
的清理由后续轮次继续，不依赖手机在线；永久身份和确认不删除。每类维护最多使用
五秒，失败保留失败信号且不阻止既有媒体工作。最大声明规模、全局清理索引的高并发
表现及生产部署仍需独立验收；此处不代表已对生产开放 staged。

## 原生终态确认与取消意图

`VocabularyWireGroupOutcome` 严格区分正向 receipt 与负向 rejection，拒绝未知字段、
原因或混合结果；匹配原 book/group 及完整有序成员后才允许持久保存。宿主还验证精确
body hash、账户/工作区/replica 和当前 generation。pending 状态及完成后的简短 ledger
都禁止相反结果覆盖；旧回调即使遇到下一组，也只能幂等重放原结果。

schema 32 保留 schema 31 的原请求/正向确认，另建每组必备的 terminal state 行。
只有 31→32 迁移为旧组回填初始状态，普通重开不会补回丢失行或重置取消意图。
request cancellation 先持久保存意图，不清请求、不伪造拒绝；网络调用方必须检查
`cancelRequested` 续发同体 cancel。提交若已赢得服务端竞争，仍接受匹配的正向结果。
网络 transport 直接根据该位选择 cancel；原生 HTTP 场景已验证重开后仍发送 cancel。
生产触发和账户迁移仍须分别接入，不能据这个布尔值的存储验收声称完整跨端同步已完成。

负确认保存后仍保留冻结正文。随后用原已确认 shadow、本地当前编辑和新的校验窗口
做普通三方合并，不把未提交的发送目标当祖先。冲突明确失败，等待用户选择；测试
中的手动改字段仅代表明确选择，尚没有冲突 UI。合并与租约、修订、generation 验证
全部成功后，在同一事务压缩负 ledger、删除旧批次及子状态，所有语料 journal、
受管理 hold 和旧 outbox 仍保留。没有公开变化的 journal 收口仍是独立待办。

即使窗口 manifest 与已应用窗口相同，首次负结算也要完成上述事务；只有完成 ledger
证明已处理后，重复 plan 才可直接返回当前本地快照，保留后续编辑和下一组。

## 服务端终态决定与 HTTP 入口

0237 迁移增加只含身份、摘要、有序成员和固定原因的拒绝账本；不留请求正文。
`settleNotebookGroup` 在既有工作区/replica 保护及 book 锁内重放一个既定结果：已提交，
或已拒绝。只有确切的领域冲突和无效语料会成为终态拒绝；晚发生的领域拒绝先回滚
savepoint 中的正文、正向账本、成员与游标，再持久拒绝决定。未知 SQL、认证、超时
和提交结果不明均保持普通错误，不能据此删除冻结请求。设计原因见
[ADR 0003](adr/0003-terminal-notebook-groups.md)。

cancel 使用同一份冻结组：若提交已赢得竞争，返回原提交确认，不撤回已保存内容；
否则持久 cancelled 结果。重放校验原 replica、协议、摘要及有序完整成员；换正文或
actor 不能复用该 group。数据库触发器同样阻止旧内部接口或直接 INSERT 复活已拒绝
身份。看不到 book 时仍由既有 RLS/FK 拒绝，不改变旧权限错误。旧接口保留原异常行为，
并可继续在原迁移边界运行。

服务端已注册工作区下的 notebook capabilities、open、groups/apply、groups/cancel
及 windows/open、page、release 路由；具体请求形状与上限以
[`httpContract.ts`](../Nibomo/apps/backend/src/notebook/httpContract.ts) 和
[`routes/notebook.ts`](../Nibomo/apps/backend/src/routes/notebook.ts) 为准。每次先复用
认证/CSRF、实际 membership 和 schema readiness，再读取有字节上限的 UTF-8 JSON。
所有响应 no-store；数据库操作沿用请求 deadline。用户身份来自认证结果，公开 writer
固定没有通用目录安装权限；完整官方目录的原样创建仅按前述受限导入规则处理。
connect 复用现有 installation/replica 派生，返回同一工作区
的 book 与设备副本；客户端既不选择 owner，也不复制服务端派生算法。

HTTP 原文和新写入的 canonical 预算仍各为 2 MiB。结算解析有单独的 16 MiB 硬上限，
只为允许有界原文在工作区/数值规范化后超出写预算时仍取消或重放既有结果；全新
apply 在读取账本之后继续严格检查 2 MiB canonical 上限。旧内部接口保持原预算。

## 原生 HTTP 调度模块

transport 先检查 `lingrove.corpus` lane 和精确能力，再发送连接元数据或冻结正文；
URLSession 不使用 cookie/cache，所有重定向拒绝，按端点限制回复字节。错误仅保留
HTTP 状态和有界机器码，不把普通错误解释为终态。连接 owner/workspace 与请求前
身份比对，原 generation 贯穿连接、POST、每页及最终 apply；响应不能选择新归属。

runner 在新工作区初始化 revision-zero 本地头，再读取 shadow，不依赖语料界面先
打开。一轮至多处理一个冻结组；已知 outcome 不重发正文，未知结果沿用原字节。
结算后先释放可能来自旧状态的同身份缓存窗口，再取新窗口；已有分页暂存可续传，
只有完整校验和原子 apply 才推进本地状态。提交后的缓存释放债务以 `cleanupPending`
明确返回；它不是数据提交确认，也不触碰 held review lane。

应用由 CloudSessionRuntime 持有语料调度适配器，在既有单飞任务的旧通道成功后运行。
生产 composition root 显式创建依赖；注入模拟云服务的组合不隐式创建另一套真实网络。
公开语料只发往当前 CloudLinkedSession 选择的 API 服务，能力验证早于连接或正文上传；
私有 Anki/音频回执仍不进入公开投影。普通语料错误不改写旧通道的同步计数和恢复状态，
而通过独立、有界 report 呈现；401/410 和取消仍走既有认证、账户与 generation 边界。
保存、手动重试、下拉刷新及后台触发使用同一调度。会话内的重试门限随工作区 generation、
文档修订和端点变化失效，显式重试可以重开。重试还有独立 generation，晚到的旧失败
不能把已排队的新一轮再次封住；拒绝日志和未知请求的磁盘证据不受门限影响。

每次新窗口仍推进远端元数据修订，保证同步计划 CAS；只有实际文档变化增加编辑修订。
域值比较之外检查确定编码的公开 wire 值，既识别 NFC/NFD 原文字节变化，又避免私有
字典/Set 的编码次序把空拉取伪装成新编辑。界面只在文档修订变化时刷新；编辑保存期间
的远端刷新等写入结束后再读取。旧成功 report 不能确认较新的本地保存。

`GET .../notebook/catalog` 通过同一账户/工作区授权读取当前目录的版本、来源摘要、
完整署名说明及许可文本，不返回用户语料、不建书、不安装目录。说明/许可与数据在同一
导入 JSON 中，避免独立文件未进入运行时包。生成器编译实际 Mac 安装器和共享编码器；
日常 PR 静态检查复核完整来源清单及数据/说明/许可指纹，原生准备阶段另执行实际重导出。

账户迁移、目录的移动自动安装/升级与首次归属协调、媒体传输、大图生产接入、持久冲突
解决及真实 iPhone/iPad 和 MCP
客户端验收仍然保留。受管理 Card/评分 holds 不因语料同步成功释放。此处没有部署。
