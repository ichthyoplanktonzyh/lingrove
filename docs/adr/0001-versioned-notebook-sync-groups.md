# 语料库同步采用版本化事务通道

Nibomo 现有客户端使用闭合的同步实体集合，服务端同批操作也允许逐项拒绝；直接追加
语料实体会破坏旧客户端解码，并可能拆散语料、参与状态和练习之间的原子关系。
因此复用既有服务端、认证、工作区、存储与传输机制，为语料新增显式版本化的事务
通道；只有支持该版本的客户端接收新实体，完整业务操作组经统一校验后原子提交和确认。

本地修订、持久化行及设备专有的 Anki 绑定不作为传输协议。来源练习的待同步保护
须保留到服务端持久确认完整操作组，随后由新通道继续同步受参与状态管理的练习及
评分；独立 Card（包括仅附来源关联的 Card）保持旧通道。两者复用既有 Card/FSRS
存储、算法和历史模型，但受管理练习不向缺少参与状态能力的旧客户端暴露；此约束
同时覆盖 bootstrap、增量、Card API、复习事件和进度查询。评分只更新练习及追加历史，
参与状态由明确的参与操作独立更新，迟到的离线评分不解除远端暂停。具体约束沿用
[语料同步契约](../NOTEBOOK_SYNC_CONTRACT.md)。这是后续实现的
架构约束，尚不表示语料同步、服务端事务或跨设备验收已经完成。
