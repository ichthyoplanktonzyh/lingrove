# 内置复习模板：第一阶段设计稿

状态：待视觉与交互评审。2026-11-04。本稿描述下一阶段产品目标，不代表当前 Dev 已实现。
本次只增加设计文档与会话中的交互预览；不修改 Swift 产品实现、数据库或已安装应用。

## 已确认的产品约束

- 日常路径：语料库中加入复习 → 留在语料库继续阅读 → 从复习首页开始一轮。
- 不将立即复习当前语料、逐张制卡、字段组装或 Markdown 编辑作为加入的必经步骤。
- 加入时按默认模板从当前义项取材；一份内容默认产生一个练习，不自动叠加反向、听音、挖空任务。
- 用户管理想记住的内容；卡片与调度是实现单位，模板定制是进阶能力。
- 复习内容跟随语料更新，保留稳定练习身份、已有评分和调度记录。
- Lingrove 和 Anki 仍是同级入口，分别拥有参与状态和历史；共享处理能力不要求共享编辑界面。
- 外层导航继续保留个人语料库、复习、进度。本稿不解决已报告的窗口跳变；它仍是单独的待修问题。

## 设计范围与可评审产物

本阶段提供一个「表达与语境」默认模板的三种数据密度、问题/答案状态、Mac/窄屏效果，
以及模板编辑器结构草图。预览使用纯合成语料与原创配图示例，没有真实用户资料。
使用同一个 harbor 义项观察资料逐步增加时的布局变化，而非用不同单词掩盖差异。

预览中的显示答案、补充资料展开、样本/设备切换、模板复制、内容开关、例句规则、
保存和设为默认仅作用于当前预览，不写入应用。评分只是结束本次演示，不计算 FSRS 间隔。
未提供音频样本，因此不出现假播放按钮，也不声称已经验证发音。
编辑器目前是可操作的结构稿，不是完整模板编辑实现：名称编辑、区域排序、自定义区域、
退出未保存确认以及应用到已有内容将在结构获认可后细化。

## 默认模板：表达与语境

### 问题面

以表达为唯一视觉中心。语种/内容类型为次要信息，提示「回忆这个表达的含义」。
此默认模板不在问题面显示释义、翻译、图片说明、笔记或解释，也不自动展示例句，
避免泄露答案。可用的既存表达音频未来可以提供手动播放；不自动生成或播放。

### 答案面

顺序固定为：核心含义 → 使用语境 → 辅助图片 → 可展开的补充资料 → 来源入口。
揭示答案时保持表达区域、外层标题、窗口尺寸和操作区的位置稳定。
Mac 原生实现中只允许内容区滚动；新增答案不得先滚到辅助图片或笔记，遮住核心含义。
会话预览采用自然页面高度以适应嵌入容器，不用于验收原生窗口尺寸稳定性。

| 区域 | 来源 | 默认呈现 | 缺失行为 |
| --- | --- | --- | --- |
| 表达 | entry.expression | 问题主体，答案揭示后仍保留 | 必需；阻止该项加入并指出缺失 |
| 核心含义 | 当前 sense.meaning | 答案首要信息，完整显示，不以静默截断或 AI 摘要替代 | 必需；不拼接其他义项代替 |
| 使用语境 | 已绑定的一条完整例句 | 原文与翻译成组，保留准确的表达范围高亮 | 无可用完整例句则省略整个区域 |
| 例句翻译 | 同一例句的 translation | 弱化颜色与字号，直接显示 | 缺失就省略，不现场请求翻译 |
| 辅助图片 | 当前义项富内容中的一张已绑定图片 | 保持原比例，可展开查看原图；图片说明在答案面 | 缺失/不可读时不留巨大空框；提供轻量来源状态 |
| 补充资料 | sense.note 与 sense.content 的文字块；可选的已存解释 | 保留标题、段落、列表、粗体和斜体，默认折叠 | 空区域连同标题一起省略 |
| 来源入口 | 稳定义项身份 | 返回原语料的辅助操作，避免放到评分旁成为主操作 | 来源失效时明确标记，不跳到其他内容 |

细节：

- 义项含义是核心，不把所有富文本块拼成一个必须阅读的答案。
- 补充资料中笔记和富文本按来源分组；不按相似度擅自删除用户文本。
- 同一张已展示图片不在补充资料中重复。额外图片仍可在完整语料中查看，后续定制可放开数量。
- 已存解释可以成为模板选项；内置默认先不自动堆入全部解释，以免同义解释重复。
- 内容为空不是网络失败，不制造「暂无」占位；媒体读取失败与字段为空需要区分。
- 数据虽然支持富内容，但目前 `VocabularyContentBlock` 是文字/图片，文字格式为
  paragraph/heading/bullet + bold/italic。不要把它当作任意 HTML 编辑器。
- 音频现由 `ReviewMaterialPlan.audio` 管理，不是每个义项都必然携带的字段。

### 多来源选取：建议规则，待评审

1. 若加入动作明确携带当前正在阅读的例句，优先绑定该完整例句。
2. 否则选择该义项最早收藏的有效完整例句，以 createdAt、稳定 ID 排序打破平局。
3. 加入时记住选定的例句 ID；后续新加另一条例句，不悄悄换掉已有题目的语境。
4. 首张图片按义项内容的用户排序选取，加入时绑定 block ID；后续重排不改变已有选择。
5. 模板定义选取规则，具体练习记录实际绑定，不把某个义项的 block/example ID 存进通用模板。
6. 只有片段而无完整例句时，本默认模板先显示表达与含义；片段仍可从来源语料读取。

是否允许用户为义项指定「首选复习例句/图片」是后续可选扩展，不作为这轮默认加入的前置操作。

## 三组验收样本

全部为合成内容，含义相同：harbor — 港口；船只停泊、避风的水域。

| 样本 | 数据组成 | 重点 |
| --- | --- | --- |
| 基础内容 | 表达、含义 | 无空图片、无空语境栏、不出现不可用播放按钮 |
| 常见内容 | 基础 + 一条完整例句及翻译 | 例句、翻译与核心答案层级清楚 |
| 丰富内容 | 常见 + 第二条例句 + 图片说明 + 标题/段落/列表/强调 + 长笔记 | 核心答案可先读，资料折叠后不压迫评分，展开后不丢格式 |

常见例句：The boat entered the harbor before the storm.
翻译：暴风雨来临前，船驶进了港口。
丰富样本另有更早的完整例句：Fishing boats returned to the harbor at dusk.
翻译：渔船在黄昏时回到了港口。
丰富样本的来源例句为前一条，所以切换模板选取规则时可以直观看到绑定结果不同。
真实实现使用已存 UTF-16 ranges 与边界校验，不以全局替换字符串实现高亮。

## 视觉规范草案

- 遵循 Lingrove 原生系统外观：中性背景、清晰的蓝色操作强调、轻量分组。
- 表达为大字号中心，核心含义次之，例句仍适合阅读，翻译和来源信息再降低层级。
- 不为每个字段套一张卡；只为完整语境组提供轻量背景，保持阅读连续性。
- 文字内容控制阅读宽度，图片不因横屏被放大成主视觉；默认不裁切语料图片。
- Mac 使用现有工作区侧栏。窄屏按问题、答案、语境、图片、补充资料的顺序单列。
- 评分操作与正文有稳定分隔；窄屏四个评分按钮分成两行，避免缩小点击区域。
- 预览中的评分文案用于视觉讨论；实际提交仍须展示调度器计算的真实间隔，不能用固定示例冒充。
- 表达区域的衬线字体是一项可评审的视觉选择。首选拉丁文字的可读衬线字形，
  中文及其他文字采用合适的系统回退；仍需用实际多语种样本校验后决定是否作为默认。
- 尊重系统字号、减少动态效果与辅助技术；图像要有描述，状态不能仅靠颜色区分。
- 本稿的富内容图片是示意插图，真实图片不进行重绘、统一滤镜或替换。

## 模板编辑器结构

入口：设置 → 语言学习 → 复习 → Lingrove 模板。普通加入不经过模板编辑器。

Mac 编辑界面由三部分组成：

1. 模板身份与状态：名称、内置/个人、保存、设为默认。
2. 内容规则：问题与答案分区，明确必需/可选内容、来源选取、展示顺序与长内容规则。
3. 实时预览：选择样本、切换问题/答案、切换窄屏，使用与真实复习一致的渲染路径。

内置模板只读；「复制并编辑」创建个人草稿，未保存前不改变默认模板。
模板预览中的样本和设备只属于编辑会话，不写进可复用模板。
编辑内容规则后立即更新预览；也要明确区分自动生成文字与单份内容的手工覆盖。
本轮不加入任意 CSS、HTML 或脚本编辑。有限排版选项应以语义作用呈现，例如主内容、
辅助内容、引用区域、默认展开方式，避免要求用户设置每段文字的像素值。

首个完整编辑器需支持：复制、改名、内容来源选择、区域排序、可选区域、有限排版、
多样本预览、保存/取消和设为默认。上下移动与键盘操作应与拖动等价。
Mac 可以两区布局；移动端可以分为规则编辑与效果预览，但保存语义必须相同。

### 模板变化与已有内容

用户已确认语料需要自动跟随更新。模板改动的传播方式尚未单独最终确认，本稿建议：

- 保存模板或设为默认只影响以后加入的内容。
- 已加入的练习保留其应用时的模板内容/版本及来源绑定。
- 「应用到已有内容」是独立操作，需要范围、变更预览与手工内容处理规则。
- 只改变视觉排版、改变来源组合、改变提问方向是不同影响。
  提问方向改变是否新增练习/如何处理调度，必须另行决定，不能默默复用原记忆进度。

## 来源更新与持久化约束

| 变化 | 建议行为 |
| --- | --- |
| 同一义项的含义修改 | 更新自动生成的核心答案，保留练习 ID、评分和调度 |
| 已绑定例句/翻译修改 | 更新对应区域；新增加其他例句不自动改绑 |
| 富文本块修改 | 更新其格式和内容；保持用户对单份复习内容的手工修改保护 |
| 可选例句/图片删除 | 按模板缺失策略移除对应区域，保留轻量可发现状态；不改绑其他来源 |
| 核心义项/必需内容不可用 | 保留题面与历史，退出可复习队列并提示处理，不能凭空替换来源 |
| 正在答题时来源变化 | 保持当前显示的问题/答案稳定；提交仍使用已显示的版本约束；冲突时明确取消/重载，不能将评分记到不同题面 |
| 媒体尚未到达本机 | 区分同步待取回与源删除；核心文字可否继续使用须与模板必需性一致 |

“保留正在显示的内容”不代表允许绕过现有 stale/CAS 检查提交评分。
允许哪些来源变更后仍提交原题，需在共享核心的命令语义中明确，而不是由 UI 猜测。

## 与现有实现的差距

| 现有边界 | 可以复用的能力 | 必须补齐/验证的部分 |
| --- | --- | --- |
| ReviewLayout / ReviewMaterialPlan | 有序来源、例句 ID、块 ID、图片说明、音频、可保存模板 | 内容角色、分组、必需/可选、缺失策略、默认模板选择与版本应用语义 |
| ReviewMaterialResolver | 统一来源解析与确定性输出 | 当前缺失来源会抛错；可选区域的降级需要共享逻辑变更 |
| Card frontText/backText | Markdown 正文、已有调度与历史 | 保持可读降级内容，但不能依赖 Markdown 推断丢失的区域角色 |
| generatedContent / refreshed | 整面生成基线与手工编辑保护 | 当前是正/背面级保护，不是逐块合并；本稿不声称已支持逐块跟随 |
| BuiltInReviewFace | 文字/富文本/本地图片/音频展示 | 按角色排版，真实图片比例、折叠与跨端等价预览 |
| ReviewMaterialEditor | 现成来源控件、模板保存和媒体准备 | 从单份材料编辑抽离为可复用规则编辑；样本不污染模板 |

现有模型只把解析结果分为 text/blocks/audio，部分语义角色在渲染前已丢失。
新增布局语义应保留结构化来源与角色，不靠分析生成后的 Markdown 猜它是什么。
本稿不决定具体 Swift API 或直接修改数据库版本。

## 跨端推进门槛

共享规则必须从 Mac 权威包导出审查过的快照；移动端不独立复制一套解析和降级逻辑。
先核对移动端实际消费版本与服务端支持范围，再确定新字段、版本与兼容策略。
新客户端不能在同步往返时静默丢失模板角色、来源绑定、手工覆盖或媒体。
界面相似不证明同步兼容；需单独覆盖加入、源更新、手工修改、可选来源丢失、媒体往返、
重试及历史保留。现有真实用户资料需要保护，不能用早期「无数据」假设跳过迁移。

## 本阶段评审与后续验收

本轮只需要确定：内容主次、丰富样本的图片/笔记比例、模板规则与预览的编辑器结构。
默认例句/图片选取、模板变化传播、手工覆盖粒度是建议规则，评审后再定实现。

后续原生验收：

- 普通加入一次明确操作成功，不弹制卡界面，不跳离语料，不开始复习。
- 默认模板在三组样本中正确降级，无空块、答案提前泄露或虚假音频。
- 复习首页启动完整一轮；来源导航只作查阅，不提供从单条语料启动一轮的主路径。
- 模板编辑取消无写入；保存与设默认含义不同；既有题面不会因修改模板而悄悄改变。
- 来源更新正确反映，媒体与手工修改不丢失，评分和历史保留。
- 真正的 Mac 和移动端按相同规则渲染；图片比例、长文本、深浅色、字号与可访问性分别验证。
