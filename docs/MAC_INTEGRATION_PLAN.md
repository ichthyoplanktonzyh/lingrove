## 产品结果

现有 AppKit/SwiftUI Lingrove 保留菜单栏、全局输入、补全、写作/阅读翻译、桌面语料
界面和 CLI；从 Nibomo 提取共同能力，使 Mac、iPhone 和 iPad 使用同一业务模型、
账户协议、语料操作规则与内置复习。不是换成 Catalyst 宿主或复制整个 FlashcardsStore。

- 收录进入个人语料库，不默认加入任何复习工具；例句只为义项提供材料。
- 内置复习是一个跨端系统；Anki 为可选的独立工具，调度/历史不混写。
- 每端有自己的离线数据库。账户归属、明确接纳本地内容、媒体、冲突、重试、评分和
  撤销沿用第三波最终规则，而非只让两种界面读到相似的 JSON。
- 登录不等于采用/上传本地内容。只同步明确授权的保存材料，不上传补全上下文、
  未保存的翻译、屏幕、日志或其他临时输入。默认离线能力不依赖账户成功。
- 无用户数据，不做旧开发 schema/快照/Anki 历史迁移；未来正常使用的持久化、手改、
  评分、取消、账户隔离仍须正确。不要为“无迁移”自动清除真实应用目录。
- 本次不切割社区等无关功能，不重设计全套 UI，不做 embedding、AI 对话或部署。

## 波次与为什么这样分

第一波是共享基础设施，详见 [MAC_WAVE_1.md](MAC_WAVE_1.md)。两名负责人各完成一个
可独立验证的深模块：

| 模块 | 交付 | 为什么放在一起 |
| --- | --- | --- |
| A：语料与复习持久化核心 | 共享 SQLite 仓储、账户/窗口绑定、语料/媒体/同步 journal、明确选入与材料更新、FSRS 与评分持久化接口 | 语料保存、材料跟随、删除影响和 journal/评分存在同事务约束，不能分给两位负责人各造一个 writer |
| B：账户与网络同步核心 | 共享认证/身份接口、会话围栏及 corpus/media/review transport 与 runner | 网络等待与重试不拥有 SQLite 真相，通过持久化接口借用 A；可独立用合成端点和记录型存储适配器验证 |

两模块不能相互复制实现或修改对方工作树。第一波实现时不依赖尚未交付的兄弟包，
跨模块接线放在集成 checkpoint 完成；不得用临时第二套数据库/调度器绕开接口。

第二波是原生 Mac 的完整用户功能，详见 [MAC_WAVE_2.md](MAC_WAVE_2.md)：

| 模块 | 交付 |
| --- | --- |
| C：桌面语料与内容入口 | 现有收藏/编辑/阅读写作/导入导出/CLI 接入共享仓储，保留桌面 UI 和业务关联 |
| D：桌面账户与同步生命周期 | 同一服务图中的账户、工作区、明确本地接纳、语料/图片/复习同步、状态及重试设置 |
| E：桌面内置复习 | 义项明确选入与准备、队列、键盘评分/撤销、暂停退出恢复、进度与来源返回；保留可选 Anki |

第二波只在第一波组合验证通过、具体公共接口与 app owner 固定后派出。负责人不改补全/
OCR/推理算法。共享 AppEnvironment/project/设置导航由契约指定一位 owner，其他模块以
独立文件提供挂接；主智能体集中解决最终接线，避免三位同时改组合根。

## 工作、验证与交付

- 每名开发负责人 `gpt-6.1-sol / max`，独立 managed worktree；完整实现再集中验证修正。
  可使用新的 `gpt-6-luna / max` 独立只读审查/执行测试，不让辅助者编写实现或测试。
- 主智能体在实现期间不轮询、不检查 diff、不主动指导或接管；只响应负责人主动问题。
  完成后主智能体读取交付、整合、必要修正与组合验证。每阶段轮换辅助者。
- 第一波派发后，按用户要求设置两小时后的本会话定时检查；只有交付完成才检查源码/
  整合。未完工的负责人不被打断。全部完成后集成验证，再派第二波。
- 真实存储/模块交互覆盖事务、关系、撤销、持久化、迟到响应和账户隔离；E2E 只保留
  核心旅程。自动化基础设施最多两次修正或二十分钟，不能阻塞大批功能交付。
- 共享 Apple flock `/tmp/lingrove-mobile-validation.lock`，每树 `build/DerivedData`，
  结束清除并验证。固定依赖只读引用/复制，禁止并发写主树缓存。第一波无 UI 改动
  不扩展手机 E2E 矩阵；普通 iPhone 为必要时的主要移动验收对象，Duo 可选。
- 所有验证用 synthetic 身份与自己拥有的 loopback 服务，不触及真实账户/邮箱/用户
  数据/正在运行的应用；无 push、部署、生产门控变更、遥测或 AWS 部署产物。
- 每波有明确 checkpoint。构建、已执行测试、人工操作、未验证真实 provider/双设备
  验收分别报告，不能用模拟服务器或 test compilation 冒充真实账户/跨端通过。

最终关键旅程：Mac 收录→手机浏览→明确选入→手机评分→Mac 接续；反向离线评分/
重试后保持同一进度；退出/切账户后旧异步结果不能落到新账户。先用独立存储与本地
真实 HTTP 验证，再记录真实服务/设备可用性；不要承诺尚未执行的验收。
